## 1. 北极星

在 Python 中复现 Hamel（1999/2001，VDI 学位论文《Mathematische Modellierung und experimentelle Untersuchung der Vergasung verschiedener fester Brennstoffe》）的鼓泡流化床气化模型与算法，使模型结果与 **Hamel 本人的模拟结果**相符。

- 主判据：Hamel 的模拟值（第 7 章出口 parity 图中的 Sim 值，以及轴向剖面图中的模拟曲线）。
- 辅判据：实验值，用于检验 Hamel 自称的偏差带（第 8 章：T ±10–15%，CO/CO₂/H₂ ±15%，CH₄ ±20%，碳转化率 ±15%）。
- 不以实验值作为“复现成功”的主要证据；也不得以实验出口反推任何模型输入。

## 2. 验收判据

### 2.1 数值前提（每个工况必须先满足）

- 最终解对**未修改的原方程**满足收敛门：气相、固相、能量各分块残差分别达标（具体阈值由 ADR 登记，不得放宽后不报）。
- 外部元素平衡（C/H/O）与总能量平衡闭合，偏差阈值由 ADR 登记。
- 状态有限、非负。

### 2.2 单工况通过（相对 Hamel 模拟值）

| 量 | 容差 |
|---|---|
| 出口（或平均自由空间）温度 | \|Δ\| ≤ 20 K |
| CO、CO₂、H₂、H₂O | \|Δ\| ≤ 0.015 mol/mol 或 ≤ 10% 相对，取较宽者 |
| CH₄ | \|Δ\| ≤ 0.005 mol/mol 或 ≤ 20% 相对，取较宽者 |
| 碳转化率 | \|Δ\| ≤ 3 个百分点 |

- 干基、湿基必须与原图一致，不得混比。
- 原文没有给出的量不参与验收，也不得用其它来源补足。各装置采用的验收量：
  - WSV400 A–F（现为后备工况）：平均自由空间温度 T̄_FRB（Bild 7.17）及干基 CO、CO₂、H₂、CH₄；原文无 H₂O 与碳转化率。A 另以 Bild 7.16 出口端温度作补充核对（同一 20 K 容差），不替代 T̄_FRB。（目标所有者 2026-10-13 决定）
  - VTT 加压 1（第 1 关）：平均自由空间温度 T̄_FRB（Bild 7.10；对应 KURKELA_1992 的 “Freeboard temperature”），碳转化率 X_C（Bild 7.10；口径为转化为干气加焦油的碳），以及 CO、CO₂、H₂、CH₄、H₂O 的摩尔分数（湿基）。共 7 个量，全部来自 `data/digitized/fig_7_10.json`。（目标所有者 2026-10-15 决定）
  - VTT 加压 2–4（第 2 关）：推进到第 2 关前，依据 Bild 7.10 对这三个工况实际读出的量登记。
  - 其它装置的验收量在推进到对应关卡前，依据 T3 覆盖表确定，并在此登记。
- 轴向剖面暂作定性比较（峰值位置、趋势、二次风处的跳变），待 T3 重新数字化模拟曲线后由目标所有者决定是否收紧。
- **读数误差的处理**（目标所有者 2026-10-14 决定）：
  - 容差不因读数误差放宽。若模型结果与合格区间某一端的距离小于该量的读数误差（`data/digitized/` 中的 `est_error`），无论落在区间内侧还是外侧，该量都判为“边界待定”，既不计为通过，也不计为不通过。
  - 边界待定只能通过**复核原图**来解决：重读该点，在 `data/digitized/` 中登记修正后的目标值或读数误差（附标定记录），再按原容差重新判定。重读后仍处在边界区内的，保持“边界待定”。
  - 只要有一个验收量处于“边界待定”，该工况就不计为通过。凭其它验收量表现良好而把边界项判为通过，属于验收例外，须由目标所有者逐案批准，并登记在 `docs/STATUS.md` 的“已决定”中。
  - §2.1 的数值前提不满足时，直接判为不通过，不进入边界判定。
- 容差只能由目标所有者修改。

## 3. 工况推进顺序

逐关推进，前一关全部通过才进入下一关（目标所有者 2026-10-14 调整）：

1. VTT 加压 1（莱茵褐煤，不循环）
2. VTT 加压 2–4（莱茵褐煤，有旋风返料循环）
3. HTW Wesseling 1（空气/蒸汽）
4. HTW Wesseling 2（氧气/蒸汽）
5. HTW Berrenrath

后备与扩展工况（不在主线关卡中，需要时由目标所有者决定是否启用）：WSV400 A–F、VTT 加压 5–8（芬兰泥炭）、VTT 常压。

调整理由：目标所有者优先验证 HTW 中试和工业装置；但表 7.1 只给出 λ，没有气化剂流量、蒸汽量和多层进气的分配，是全书数据最少的一类工况。VTT 加压的褐煤工况与 HTW 使用同一种燃料，并具备加压、二次风分级、加蒸汽、旋风返料循环这些主要物理特征，表 7.2 的运行数据最完整，且 Hamel 引用的原始文献（Kurkela & Ståhlberg 1992；Kurkela et al. 1993）可用于补齐缺口（§4.2）。按上述顺序，每一关只比前一关多一两个物理特征，走到 HTW 时，加压、分级、循环这几部分已在数据充分的工况上验证过。HTW 的数据缺口在推进 VTT 的同时设法补齐。WSV400 原定为第一关，因热值、进气温度、床料、壁面散热等关键输入缺失过多而降为后备；已完成的输入数据（`data/cases/wsv400.json`）和裁定（ADR 0003）保留备用。

数据来源：`data/digitized/`（T3 用专用工具从原图读取的模拟值与实验值）是出口值的唯一依据；`data/validation_cases.json` 只提供工况输入。`data/hamel_fig7_parity_digitized.json` 已证实存在大幅读数错误（2026-10-13 对照 Bild 7.17 原页），不得用于验收或对比；`validation_cases.json` 中的出口值在与 `data/digitized/` 逐项核对前同样不得使用。

## 4. 文献来源

1. Hamel 论文是唯一主来源。
2. 其它文献（Wirsum 1997、Hegermann、Hilligardt 等）只有在 Hamel 对该子模型明确引用时才可使用，并标注“Hamel 引用的 X（Hamel 式号/页码）”。
3. 引入 Hamel 未引用的文献，须目标所有者批准并登记 ADR。
4. 任何涉及方程的任务卡，执行者动手前须按 `hamel-source-check` 交“原文答卷”，经总司令审查通过后才能写代码。
5. 原文没有说明的地方必须如实写“原文未说明”并上报裁定，裁定结果登记 ADR，代码注释标为“解释性选择”。禁止悄悄填补。
6. 禁止用当前或旧实现反推原文。

## 5. 求解手段的边界

- **允许**（须登记 ADR）：初值构造、Vorabrechnung（预计算）、阻尼、线搜索、同伦/延拓、雅可比近似。
- **禁止**：修改残差本身，包括 clip、下限截断、强制温度、残差锚点项、按条件关闭方程项。
- 唯一判定标准：最终解使未修改的原方程满足 §2.1。求解路径上的辅助手段不改变解的正确性，残差上的修改则会改变。

## 6. 代码规范

### 6.1 主线结构

- 唯一主线为仓库内 `hamel/` 包。旧代码只存在于归档分支 `archive/2026-10-12-snapshot`（tag `archive-2026-10-12`），不在主线目录中保留。
- 从归档迁入任何函数，须同时具备：审计记录（原文答卷或转录比对结论）＋论文锚点测试。
- 模块按论文章节划分：

| 模块 | 内容 | 论文 |
|---|---|---|
| `hamel/properties/` | 物性、组分、焓、气相化学平衡 | 附录 A1 及相关章节 |
| `hamel/hydrodynamics/` | u_mf、气泡、相含率、相间交换 | 第 3.1 节 |
| `hamel/freeboard/` | 床面固体抛出、颗粒与气体在自由空间的运动 | 第 3.2 节 |
| `hamel/pyrolysis/` | 干燥、热解产率与热解气组成 | 第 4 章 |
| `hamel/kinetics/` | 异相（R1–R4）与均相（R5–R11）反应速率 | 第 5 章 |
| `hamel/balances/` | cell 物料与能量衡算 | 第 2.2 节 |
| `hamel/solver/` | Vorabrechnung、对齐迭代、阻尼 Newton–Raphson | 第 2.1、2.3 节 |
| `hamel/cases/` | 工况装配与对标 | 第 7 章 |

（章节号依据原文目录（PDF 4–5），2026-10-13 修正；以 T2 索引为准。）

### 6.2 规模与配置

- WSV400 全部通过前，`hamel/` 代码总量上限 8,000 行（不含测试）。
- 物理参数配置 ≤ 30 项；求解器参数单独成组。
- 禁止功能开关与双轨模式（如 `_thesis` / `engineering` 并存）。
- 超限须目标所有者批准。

### 6.3 命名与语言

- 反应编号、方程编号、符号一律以 Hamel 原文为准。
- 标识符为英文 snake_case，由 Hamel 符号或德文术语转写。
- 文档与注释用中文。
- 核心函数 docstring 注明来源，格式：`Source: Hamel Eq.x.y, S. N`。引用须能在 `refs/hamel/index.json` 中找到（由校验脚本检查）。
- 术语以 `GLOSSARY.md` 为准，`_Avoid_` 中列出的旧叫法不得再用。

### 6.4 继承的全局规则

- 全程 SI；唯一例外按原文登记 ADR（如 R8 内部压力换算）。
- Arrhenius 只通过统一工厂函数计算。
- 不添加 logging 框架、设计模式和抽象基类。

## 7. 测试

- 期望值必须来自论文：中间结果图表的数字化读数＞按原文公式独立手算＞性质测试（量纲、极限、守恒、单调性）。
- 用旧代码输出作为期望值的测试必须标注 `# 回归快照，非正确性证据`，且不能作为迁入门槛。
- 旧的约 1245 个测试不整体迁移，只随迁入的函数一起迁移并改写期望值。
- 默认测试集 5 分钟内跑完；单个工况完整求解标为 `slow`。
- 长求解一律带硬超时；超时即记录 TIMEOUT，不无限等待。

## 8. 角色与流程

| 角色 | 担任者 | 职责与权限 |
|---|---|---|
| 目标所有者 | 用户 | 保留：章程本身、验收判据（§2）、工况推进顺序（§3）、引入 Hamel 未引用的文献（§4.3）、超出规模上限（§6.2）、合并到 main。对总司令的任何决定有否决权 |
| 总司令 | Claude（独立会话） | 协调与决定：起草和维护任务卡、分派执行者与优先级；验收文档类与数据类 PR；裁定原文空白与歧义并批准 ADR（每项决定写明依据，目标所有者可否决）；运行偏离检查，发现偏离时叫停。不写 `hamel/` 下的业务代码，不审查自己起草的内容 |
| 主执行者 | cursor | 按任务卡完成实现、转录、数据整理等工作；越界或超预算即停下上报 |
| 审查者 | codex | 审查代码类（`hamel/`、`tools/`）、原文转录类和 ADR 类 PR，以及总司令起草的内容 |
| 辅助执行者 | 目标所有者，或其另行指派的 agent | 人工看图读数等需要人工判断或图形界面工具的工作 |

### 审查分级

| PR 类型 | 审查方 |
|---|---|
| 代码（`hamel/`、`tools/`）、原文转录、ADR | codex |
| 纯文档、任务卡、STATUS、数据录入 | 总司令 |
| 总司令起草的内容（任务卡、ADR 草稿、skill 文本、章程修改草案） | codex 或目标所有者 |

任何一方都不审查自己完成的工作。

### 审查方的临时替代（v0.9，2026-10-16 目标所有者决定）

codex 额度不足时，上表中由 codex 担任的审查，可由**目标所有者另开的独立 Claude Code 会话**暂代。条件：

1. 该会话由目标所有者开启，不是总司令会话，也不由总司令派生；它不审查自己完成的工作。
2. 审查时须对照页面图像等原始材料独立核对，不采信 PR 描述和起草方的推理。
3. 审查评论开头写明审查方身份（例如“独立审查（Claude 会话，暂代 codex）”）和所审提交。
4. 暂代审查方与起草方的分歧，由目标所有者裁决。
5. 何时启用暂代、何时改回 codex，由目标所有者决定；codex 恢复后可随时改回，已完成的暂代审查继续有效。

### 独立性

标为“独立”的任务（如原文独立转录）须在**全新会话**中执行：执行者在该任务中只接触任务卡允许的材料，不沿用接触过旧代码、旧转录或旧结论的会话。独立性取决于会话接触过的材料，不取决于使用哪个 agent 产品。

### 工作流

1. 每张任务卡一个分支，完成后提 PR。同一 PR 内同时更新 `docs/STATUS.md` 中受影响的条目（任务行、队列、待定项），不另开同步 PR。任务卡不设状态栏，任务状态只以 STATUS 的任务表为准；v0.10 之前的任务卡中已有的状态栏停止维护，不必回改。
2. 审查方按上表审查：范围、验收证据、原文答卷、偏离信号；结论写进 PR 评论（不能只留在审查方自己的对话中）。
   - 批准写成该 PR 审查通过后的最后一个提交，不再单开批准 PR：ADR 在自身 frontmatter 中改为 `status: accepted` 并写批准记录；任务卡的批准只更新 STATUS 任务表中对应一行（状态与批准记录），不在任务卡内另记状态。该提交只改状态与记录；审查方确认该提交未改动已审内容后即可合并，内容若有改动须复审。
   - codex 额度可用时，ADR 类审查优先由 codex 担任，以保留跨模型的独立性（§8 临时替代仍适用于额度不足时）。
3. 目标所有者合并，或明确指示某个 agent 代为合并指定的 PR。agent 不得自行合并，不得直接 push main。
4. 每次会话结束时工作树必须干净（已 commit）。

任务卡模板见 `docs/tasks/_TEMPLATE.md`。

## 9. 偏离信号

每次交接运行偏离检查脚本，任一项触发即要求总司令审查：

- 工作树不干净；
- 新增配置项没有对应 ADR。例外（目标所有者 2026-10-14 决定）：**物理参数**字段若与 `data/cases/*.json` 中的同名字段对应，且该字段的 `status` 为 `source`（原文给出）或 `derived`（由原文数据按写明的公式换算），并在 `source` 中给出页码，即视为有出处，不必另写 ADR。`status` 为 `missing` 的字段（其取值须经裁定），以及**所有求解器参数**（阻尼、容差、初值策略等 §5 所列手段），仍须在正式 ADR 中登记；
- 单张任务卡净增代码超过 800 行；
- 新文件名呈阶段后缀模式（如 `_r12_r5`、`_v7`、`_stage3`）；
- 连续 2 周没有任何工况指标变化（此项触发后须目标所有者确认才能继续）。

总司令审查只问五个问题：

1. 推进了哪个工况指标？
2. 是否修改了方程或判据？如果是，依据是否回到原文？
3. 是否引入了新的平行实现或开关？
4. 是否有原文空白被悄悄填补？
5. 交接后工作树是否干净？

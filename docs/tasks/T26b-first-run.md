## 目标

按 ADR 0030 执行第 1 关（VTT 加压 1）的基准运行与 S1–S16，提交首次运行报告。验收按 CHARTER §2，只对 Hamel 模拟值（`data/digitized/fig_7_10.json`）。

## 执行顺序

1. **先跑基准与 S1**（各自独立进程，可并行）。两者结束后（收敛、未收敛、超时或出错均算结束），立即提交一次中间报告与 STATUS 更新：这是第 1 关的第一个工况指标。
2. 基准收敛时，用 T26a 第 11 项的入口对基准最终状态做数值加密，结果单独成节。
3. 再跑 S2–S16。可并行，并行数在 PR 中写明；每次运行仍各自受 ADR 0037 的硬超时约束。
4. 全部结束后提交完整报告（`reports/` 下的 Markdown 与 JSON，目录名在 PR 中说明）。

## 规则

- 不按任何运行结果修改冻结项、代码或工况文件（ADR 0013、ADR 0030、ADR 0040）。敏感性只报告。
- 每次运行的状态如实记录（CONVERGED、NOT_CONVERGED、TIMEOUT、DOMAIN_STOP、ERROR），不省略、不重跑挑选。
- 运行中发现程序错误时停止该运行，停下上报（错误、证据、影响哪些运行）；修正另立任务卡，修正后全部运行重跑。
- 基准未收敛时仍按顺序跑完 S1–S16，并在报告中写明基准状态。

## 交付物

- 中间报告（基准与 S1）与完整报告；运行日志的位置
- `docs/STATUS.md` 中 T26b 一行与“工况指标”表

## 停止条件

发现程序错误、运行环境无法完成运行、或需要越出本卡范围时，停下并在 PR / STATUS 中写明。

## 目标

T30 的验收结论是**不通过**：7 量中 `X_C`、`CO2`、`H2`、`H2O` 在合格区间外，`T̄_FRB`、`CH4` 边界待定。已经由外部核算确认（见“已知事实”）偏差**不是元素账错误**，而是反应路径的分配问题。本卡把“分配”这一步**读出来**，不再靠推断：

给出基准收敛解上**逐格、逐相（气泡／悬浮／自由空间）的 R1–R11 进度**（mol/s），以及各格各相的温度、压力、相体积、气相摩尔流与 `O2`／`H2`／`H2O`／`CO`／`CO2`／`CH4` 的浓度和摩尔分数，并据此给出**氧账与水账**：氧在 R1／R5／R6／R7／R10 之间的去向份额，水在 R2／R5（气泡相）／R7／R8／R9／R11 之间的生成与消耗份额。

产出是**诊断结论**，不是验收结论：本卡不改判定，不改任何数值，也不产生新的验收量。

## 已知事实（T30 结果，供核对，不得当作输入改模型）

1. 基准 `CONVERGED`：16 轮 / 180 次 / 5 474,4 s；`T̄_FRB` 1174,58 K、`X_C` 86,639 %、`CO` 0,16550、`CO2` 0,11152、`H2` 0,15081、`CH4` 0,017477、`H2O` 0,060271（湿基）。
2. 入口元素通量（由 `data/cases/vtt_pressurized.json` 的工况 1 与 `data/...fuels` 的工业分析独立复算）：C 0,6103、H 0,9047、O 0,8047 mol/s；入口水（燃料水分 + 蒸汽）合计 0,1901 mol/s。
3. 出口气 0,044879 kg/s；模型水净分解约 0,084 mol/s（吃掉了所供水的 44 %），Hamel 目标侧为净生成约 0,020 mol/s。这是全部偏差里唯一“量级不对”的一项。
4. 用 `hamel/properties/thermo.py` 的化学势算得 1182 K 下 `K_WGS` = 1,307；模型气相 `K_act` = 1,686（逆向驱动），目标侧 `K_act` = 0,496（正向驱动）。两侧都远离平衡、且分居异侧 → R8 是被动的，不能作为调整对象。
5. 耗氧反应的氧级数：R5 气泡相 0,3、悬浮相 0,5；R1／R6／R7／R10 均为 1。在 O2 趋零处低阶项占优。

以上 2–5 是**外部核算得到的事实**，本卡要求执行者用代码在真实解上**复算并核对量级**（允许与上列数值有舍入差），不复算就不能进入结论。

## 范围内

### A. 仪器（只记录，不改任何公式、常数、顺序、容差）

1. **逐反应进度账**：在 `hamel/solver/residual.py` 加一个**默认关闭**的记录开关。开启时，`_Context` 在每次 `_apply` 处累加 `(zone, cell, phase, reaction, extent_mol_s)`，并把该块的温度、压力、相体积、气相摩尔流与上列组分的 `c`／`y` 一并记下。
   - 记录必须落在**唯一的调用点**（`_apply` 的 sink 参数或等价的单一入口），不得在每个反应式里各写一遍。
   - 默认路径（开关关闭）必须与现在的行为**逐位相同**：同一个 `evaluate_residual` 调用的返回值不得因加参数而变化。
2. **只在收敛解上开启一次**：`hamel/solver/driver.py` 在通过 §2.1、2(b) 复核与 ADR 0059 检查线**之后**，对最终 `x` 再调一次 `evaluate_residual(..., ledger=True)`，把结果写进 `diagnostics["reaction_ledger"]`。
   - 这次调用**不得**进入牛顿迭代、雅可比、初值构造或任何试探路径（保证求解时间和数值都不受影响）。
   - 记录块必须小（8 格 × 2 相 + 8 格自由空间 × 11 反应量级），不得把逐次迭代的数组塞进报告。
3. **便于复算**：把最终打包状态与冻结量写到 `.scratch/t31/`（`state.npz`、`frozen.pkl`），使账目可离线重算，不必再跑 5 500 s。该目录已在 `.gitignore`，不入库。
4. **报告侧**：`tools/driver_report.py` 增一节“反应路径账”，渲染 A 项的账目与下面 C 项的份额表；判定逻辑仍只来自 `hamel/cases/judge.py` 与 `targets.py`，本卡不碰。

### B. 运行（一次）

基准运行：`data/cases/vtt_pressurized.json` 工况 1，`adiabatic=False`，配置与 T30 **逐字相同**（`outer_round_limit=26`、进程级硬墙钟 28 800 s、`signal.setitimer(ITIMER_REAL, limit + 0.05)` + `_Timeout(BaseException)`，超时记 `TIMEOUT`、退出码 2、先落盘再判定）。

不跑 S1（绝热对照的失败另有归属，见“范围外”），不跑任何敏感性运行。

### C. 必报内容

1. **氧账（逐格 + 全床）**：进入该格的 O2（进口气 + 由下格来），与 R1／R5（气泡与悬浮分开）／R6／R7／R10 各自的 O2 消耗量与份额；该格出口 O2。要求逐格闭合（相对差 ≤ 1×10⁻⁹），并给出全床合计。必须能回答一句话：**氧在床底几格之内被谁吃掉。**
2. **水账（逐格 + 全床）**：R2 消耗的水、R5 气泡相消耗的水（若有）、R7 生成、R8 正／逆向、R9 消耗、R11 消耗、燃料水分释放、蒸汽进料；净收支与 0,1901 mol/s 进口水对照。必须能回答：**水在哪一格、被哪个反应夺走。**
3. **H2 与 CH4 账**：R2／R4／R8／R9／R11 的产氢与耗氢，R5／R6／R7 的耗氢；CH4 的生成（热解与 R11）与消耗（R7／R9）。用于判断 H2 与 CH4 偏高是“产得多”还是“烧得少”。
4. **碳账**：R1／R3 的焦炭消耗与 CO／CO2 生成、R5 的 CO→CO2、R8 的移向，与 `X_C` = 86,639 % 对照。用于判断 `X_C` 高是“焦炭烧得多”还是“气化得多”。
5. **局部条件表**：各格的气泡／悬浮两相 `c_O2`、`c_H2`、`c_H2O`、`y_O2`、温度。特别要给出 R5 与 R6 的**竞争交叉点**：用本次解的实际速率常数，算 `c_O2*`（使 R5 与 R6 对 O2 的消耗速率相等），并与该格实际 `c_O2` 比较；逐格报“低于／高于交叉点”。
6. **假设判别表**（预登记判据，不得事后改）：

   | 假设 | 判据（预先登记） | 结论栏 |
   |---|---|---|
   | H1：R2 过量夺水 | R2 的水消耗占全部净耗水的 **≥ 50 %** | 成立／次要／不成立 |
   | H2：R5 抢氧致 R6 饿死 | R5 的氧消耗份额 **≥ 50 %**，且 R6 所在格的 `c_O2` 低于交叉点 `c_O2*` | 成立／次要／不成立 |
   | H3：R9／R11 为主要水汇 | R9 与 R11 合计水消耗 **≥ 20 %** | 成立／次要／不成立 |

   份额按 20 %／50 % 分档，**< 20 % 记“可忽略”**。判据在本卡预先登记，看到数字后不得移动阈值。
7. **算术对照（明确标注“非模型结果”）**：若把 R5 实际消耗的那部分 O2 全部改由 R6 消耗（受 H2 存量上限约束），生成的 H2O 上界是多少、`H2O`／`H2` 两个量的偏差能闭合多少。只做算术，**不得**把结论写回模型或作为调参依据。
8. **数值不变声明**：本次运行的 7 个验收量与 T30 记录值相对差 ≤ 1×10⁻⁹，四块残差同样；外层轮数／内层次数与 T30 相同（16 / 180）。**不满足即停止**（说明记录改动了数值）。
9. **运行时长对照**：与 T30 的 5 474,4 s 对比，证明记录开销可忽略（本卡要求为同一量级，不做严格阈值）。

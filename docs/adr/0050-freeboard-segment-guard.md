# 自由空间参考轨迹以解析段数代替物理时间上限作终止保护（修订 ADR 0028 的 `freeboard_time_limit_s`）

> **状态：提议中。** T26j（PR #133）按停止条件停下：ADR 0048 的粒级内取样下，第 1 次预计算的参考记账报“积分时间达到上限 80,0 s，归宿仍未确定”，初值构造没有开始。本 ADR 只改轨迹推进的终止保护，属求解器参数（CHARTER §5），不改方程、捕获判据、记账与冻结值。按 CHARTER v0.10 §8，审查方审查后批准，目标所有者可否决。

## 依据

- ADR 0028 把 `freeboard_time_limit_s = 80 s` 登记为“只用于报错”：到时颗粒尚未回落或带出就失败，不改判。它是数值积分时代防止不终止的保护，不是 Hamel 原文的量；原文的轨迹计算（S. 45–49）没有时间上限。
- ADR 0047 改为逐格常系数解析解后，每一段都是闭式：一段走到格边界、u_P 穿过 ū_g 或 u_P = 0 为止，一次求出。轨迹在有限段内终止，只剩两种可能不终止：(1) 中性格 |ū_g − v_t| → 0，ADR 0047 第 3 项已报告并停止；(2) 在稳定界面两侧无限往复，ADR 0047 第 3 项与 ADR 0048 第 2 项的捕获判据处理。物理时间长短本身不是不终止的信号。
- **总司令复核**（工况 1 初值点第 1 轮剖面，`reports/t26h-trajectories/precalc_old.json`，ADR 0048 取样，粒级 1–7 × {N_d = N_φ = 8、16} × σ_φ ∈ {0,05、0,1、0,15}，共 175 616 条轨迹；时间上限放到 10⁷ s，只作诊断）：
  - 全部轨迹定归宿，最多 **21 段**（现行 δ 判据）；归宿时刻的 99 % 分位 45 s，最大 2 794 s，超过 80 s 的 827 条。
  - 超过 80 s 的原因是**慢速穿越**而非界面往复：例如 d = 0,261 mm、φ_S = 0,887 的子样本在格 5 的 ū_g − v_t = −3,5·10⁻³ m/s，穿越 0,29 m 的格需约 80 s。这段停留是模型给出的物理停留，计入该格自由状态（ADR 0016 第 9、10 条），不应因时间长而判为失败。
  - 把捕获判据换成不依赖 δ 的精确判据（界面往复的回程速度单调不增、且整个往复留在半格 R* 内即判捕获）作对照，归宿份额与现行 δ 判据逐项相同，最多 16 段。因此本 ADR 不改捕获判据。
  - 粒级 3 在 N_d = N_φ = 8、σ_φ = 0,1 时：回落 0,4094、带出 0,0932、捕获 0,4973，与 T26j 报告中时限放到 5 000 s 的诊断一致。

## 裁定（求解器参数）

1. **撤销** `freeboard_time_limit_s` 作为失败条件（ADR 0028 表中该行）。轨迹推进不再按物理时间截止。
2. **新增** `SolverConfig.freeboard_max_segments = 1000`：一条参考轨迹的解析段数（`advance_cell` 的调用次数）达到上限仍未定归宿即失败，报告粒径、球形度、起点、所在格、已走段数与已用物理时间，不改判成回落、带出或捕获。上限约为工况 1 实测最大段数的 50 倍，只防程序错误与未覆盖的往复情形。
3. ADR 0047 第 3 项的中性格停止、ADR 0034/0047 的 δ_u、δ_h 捕获判据、ADR 0048 的半格 R* 与“最后一次进入 R*”记账都不变。
4. 凡现行代码中以 `freeboard_time_limit_s` 作为推进截止的地方（含 `trace_until_fate` 与其它调用 `advance_cell` 的推进循环）一并改为段数保护；`advance_cell` 的剩余时间参数取无穷或删除。以 `freeboard_time_limit_s` 作其它用途的地方（如 `tools/run_prep.py` 的适用性表），由实现逐一列出，删除该字段或改用段数，在 PR 中说明。
5. **报告**：每次预计算记录全部参考轨迹的最大段数、归宿时刻的最大值与 99 % 分位，以及归宿时刻最长的 (粒级, d, φ_S, 起点)。

## 实现约束

- 注明 `求解器参数：ADR 0050`。
- 测试：(a) 构造 |ū_g − v_t| 很小但不中性的格，物理穿越时间远大于 80 s，轨迹正常定归宿，自由状态停留按解析时间计入；(b) 段数达到上限时失败并给出报告字段（可用很小的上限构造）；(c) 原以短时限触发失败的测试改为段数上限或删除，在 PR 中逐一说明。
- ADR 0030 冻结清单的数值检查来源补列 ADR 0050；ADR 0028 加补注。
- 由 T26j 在 PR #133 内实现并重做 C 部分验证（见任务卡 F 部分）。

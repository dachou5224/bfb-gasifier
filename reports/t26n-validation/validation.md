# T26n 验证：ADR 0053 的两项补入，余项定位与修正

> 工况 1，`data/cases/vtt_pressurized.json`。运行记录 `reports/t26n-validation/alternation.json`
> （`tools/alternation_diagnostic.py --loops 4 --out reports/t26n-validation/alternation.json`，
> 墙钟 1 331 s；PR #144 审查 P2 修正 `signed_drain` 后重跑，见第 4 节）。
> ṁ_ref = 0,0130278 × (1 − 0,118) = 1,14905·10⁻² kg/s（ADR 0012 的参考流 m_ref）。

## 判据（任务卡预先登记）

初值构造每次交替收敛固相上的最底格整体固体闭合差满足 ADR 0017 第 13 项：
|残差|/ṁ_ref ≤ 1·10⁻⁶。

## 结论

- **A 已实现**：`bed_downflow` 的反应汇减去床区干燥与热解的失重，最底格外排加上随排灰离开
  的未转化燃料；两项由同一函数 `precalc.bed_release_terms` 给出，预计算取上一次预计算的
  释放分布、`initial.recompute_flows` 取当前预计算的释放分布。
- **B 已定位并修正**：补入两项后剩下的约 2,5·10⁻⁷ kg/s 是 ADR 0014 A5 余额里“随未转化
  燃料离开的灰”的口径错误——原式把湿基灰分比乘到**实际**燃料出口流上，对已经干燥的出口
  流漏掉了其干物质的灰。修正后床区灰的边界收支差 ≤ 2,1·10⁻¹⁴ kg/s，闭合差降到收敛行残差
  的量级。
- **C 已报告，判据在第 3 次交替上未达（如实保留）**：正式写法可达的两次交替都满足判据
  （1,3·10⁻¹⁰ 与 1,0·10⁻⁸）。诊断按卡上写法把 A5 的负余额取负值、继续交替，多做的两次
  交替为 −1,11·10⁻⁶ 与 +4,50·10⁻⁷；**第 3 次仍超闭合门 1,11 倍**。逐项余项列于第 3.3 节：
  该次闭合差与固相牛顿自身的归一整行残差（8,96·10⁻⁷）同量级，床区灰的边界收支差为
  −2,1·10⁻¹⁴ kg/s，但按卡上判据，这一次交替**不通过**，本卡不把它写成通过。
- 正式路径（不取负余额）仍在第 3 次预计算按 ADR 0014 A5 的符号检查停止
  （`带出灰多于燃料带入灰`），与 T26m 相同；本卡禁止改 A5 的符号检查，主求解的内层未运行
  （内层 0 次）。

## 1. A：ADR 0053 第 1–3 项

| 项 | 实现 |
|---|---|
| 反应汇减失重 | `precalc.bed_release_terms` 取 `_pyro_flows` 的床区部分（水分、热解气体、苯、萘按摩尔质量换算），与床区气相源项 `FrozenQuantities.pyro_bed_mol_s` 是同一组量，不按产率重算 |
| 外排加燃料出口 | 同一函数取最底床格的 `undried_exit_kg_s[-1] + dried_exit_kg_s[-1]`（湿燃料 + 干燥后燃料的出口流，逐粒级求和） |
| 预计算的求值状态 | `precalculate(..., previous_release=...)`：驱动 `driver` 的 `holder["release"]` 保存上一次预计算的 `ReleaseDistribution`；第一次预计算为 `None`，两项取 0 |
| 初值构造的求值状态 | `initial.recompute_flows` 用 `context.released`（当前预计算的释放分布） |
| 共用函数 | 两处都调用 `precalc.bed_release_terms`，没有复制公式；`bed_downflow` 新增 `loss_kg_s`、`fuel_exit_kg_s` 两个入参，默认值使原调用不变 |

测试（`tests/test_precalc.py`、`tests/test_initial_state.py`）：

- 小例子上补入两项后闭合差为零到舍入；去掉任一项，闭合差恰为该项；
- `bed_release_terms` 的失重等于床区气相源项的质量流（自由空间格的气体不计入），燃料出口
  逐粒级求和；
- 预计算与 `initial.recompute_flows` 在同一状态、同一释放分布下的 Ṁ_ab 逐位相同
  （`np.array_equal`），闭合差逐位相同。

## 2. B：余项定位与修正

### 2.1 定位

对每次交替的收敛固相，按两套算法交叉核对（下表是**B 修正前**、即只补入 A 的两项时的值）：

| 交替 | 闭合差（补入两项后） | 床区灰的边界收支差 | release 自身质量闭合 | 闭合差/ṁ_ref |
|---|---|---|---|---|
| 1 | −2,3453·10⁻⁷ | −2,3453·10⁻⁷ | 4,6·10⁻¹⁴ | −2,04·10⁻⁵ |
| 2 | −3,3093·10⁻⁷ | −3,3105·10⁻⁷ | 4,7·10⁻¹⁴ | −2,88·10⁻⁵ |
| 3 | −2,6779·10⁻⁷ | −2,5522·10⁻⁷ | 4,7·10⁻¹⁴ | −2,33·10⁻⁵ |
| 4 | −2,4780·10⁻⁷ | −2,5298·10⁻⁷ | 4,7·10⁻¹⁴ | −2,16·10⁻⁵ |

- 闭合差与床区灰的边界收支差 `ash_gen_bed + returning − ejection − drain_ash` 逐位一致
  （相差不超过第 3 次交替的固相行残差 1,3·10⁻⁸）。焦炭行在收敛解上为 0（归一整行残差
  5,7·10⁻¹⁰–9,0·10⁻⁷），`release` 模块自身的质量闭合为 4,6–4,7·10⁻¹⁴ kg/s，因此余项不在
  `release`、也不在两项补入的公式里。
- 把 A5 的 `drain_ash = ash_in − carried − fuel_ash` 代入，床区灰收支差化为
  `fuel_ash − (ash_in − Σ ash_gen)`。`ash_in − Σ ash_gen` 就是“燃料带入灰 − 热解生成的灰”，
  即随未转化燃料离开的灰（干基）；A5 的实现把它写成湿基灰分比乘实际出口流。

| 交替 | 燃料带入灰 ash_in | 热解生成灰 Σ ash_gen | ash_in − Σ ash_gen | A5 的 fuel_ash（原式，修正前） | 差 |
|---|---|---|---|---|---|
| 1 | 4,9414·10⁻⁴ | 4,9210·10⁻⁴ | 1,9876·10⁻⁶ | 1,7530·10⁻⁶ | +2,345·10⁻⁷ |
| 2 | 4,9414·10⁻⁴ | 4,9102·10⁻⁴ | 3,0749·10⁻⁶ | 2,7439·10⁻⁶ | +3,310·10⁻⁷ |
| 3 | 4,9414·10⁻⁴ | 4,9174·10⁻⁴ | 2,3561·10⁻⁶ | 2,1009·10⁻⁶ | +2,552·10⁻⁷ |
| 4 | 4,9414·10⁻⁴ | 4,9176·10⁻⁴ | 2,3346·10⁻⁶ | 2,0816·10⁻⁶ | +2,529·10⁻⁷ |

差值与上表的床区灰收支差逐位相等（符号相反）。修正后 `fuel_ash` 与 `ash_in − Σ ash_gen`
的差为 7,2·10⁻²¹…1,0·10⁻¹⁹ kg/s（`alternation.json` 的 `fuel_ash_kg_s` 与
`ash_in_kg_s − ash_gen_total_kg_s`），即该项成为恒等式。

### 2.2 原因

`ReleaseDistribution.dried_exit_kg_s` 已经是干基质量（`(1 − 水分) × 当量出流`），
`fuel_top`/`fuel_drain` 因此是**实际**燃料出口质量。原式用湿基灰分比
`ash_in / fuel_kg_s`（= ash_wf·(1 − m)）乘这个实际质量，等于假设离开的燃料与进料同为
湿基；已干燥的那部分出口流不含水，其灰分被少算了 `ash_wf·m`：

```
正确值  = ash_wf · [(1 − m)·undried_out + dried_out]
原式    = ash_wf · (1 − m) · (undried_out + dried_out)
差      = ash_wf · m · dried_out
```

数值核对（第 4 次交替）：`dried_out` = 床区 3,658·10⁻⁵ + 自由空间顶 1,327·10⁻⁵ = 4,985·10⁻⁵ kg/s，
`0,043 × 0,118 × 4,985·10⁻⁵ = 2,53·10⁻⁷` kg/s，与余项一致。

### 2.3 修正

`precalc._drain_terms` 的 `fuel_ash` 加上 `ash_wf · m · Σ dried_exit_kg_s`（同一份
`ReleaseDistribution`，不新增输入）。ADR 0014 A5 的余额式
`drain_ash = ash_in − carried − fuel_ash`、预计算中的符号保护、冻结量定义均未改。
修正后床区灰的边界收支差（4 次交替）为 3,4·10⁻¹⁶、1,7·10⁻¹⁶、−2,1·10⁻¹⁴、2,6·10⁻¹⁵ kg/s。

### 3.3 余项逐项（交替 3，判据未达项）

`alternation.json` 的 `solids[2]` 列出该状态整体固体的全部进出项。闭合差
−1,27·10⁻⁸ kg/s 的分解如下（kg/s）：

| 项 | 值 | 说明 |
|---|---|---|
| 床区焦炭行（`char_gap_kg_s`） | 0（≤1·10⁻¹⁶） | 固相牛顿已收敛，焦炭方程逐格成立 |
| 床区灰的边界收支差 | −2,1·10⁻¹⁴ | `ash_gen_bed + returning − ejection − drain_ash`，舍入量级 |
| `release` 自身质量闭合 | 4,7·10⁻¹⁴ | 释放分布模块的自检 |
| 固相牛顿的归一整行残差 | +8,96·10⁻⁷ | 该次迭代的收敛门，各行残差之和与之同量级 |
| **最底格闭合差** | **−1,27·10⁻⁸**（/ṁ_ref = −1,11·10⁻⁶） | 判据 1·10⁻⁶，**未达** |

即：物理量与舍入量都已降到 10⁻¹⁴ 量级，剩下的是牛顿收敛门对应的行残差之和；但按 ADR 0017
第 13 项该次交替未达，需在停止边界内如实记录。

### 3.2 正式路径的停止点

第 3 次预计算的 A5 余额为 −2,2787·10⁻⁴ kg/s（带出灰 7,1961·10⁻⁴、带入灰 4,9409·10⁻⁴、

诊断把它取负值后继续，得到交替 3、4。

## 4. PR #144 审查 P2 的修正与重跑

审查指出：`tools/alternation_diagnostic.py` 的 `signed_drain` 复制了旧 A5 计算，没有本 PR 在
`precalc._drain_terms` 里新增的 `ash_wf·m·Σdried_exit`；`guarded` 在正式 `_drain` 因负余额
报错后改调它，于是恰在第 3 次预计算切回旧口径，工具“与正式写法只差负余额不停止”的声明不成立。

修正：`signed_drain` 直接复用 `precalc._drain_terms` 的返回值，只不施加 `ash_out > ash_in`
的符号拒绝；不复制公式，最底格灰分为正的定义域检查仍由 `_drain_terms` 报错。

| | 修正前（复制式） | 修正后（复用 `_drain_terms`） |
|---|---|---|
| 第 3 次预计算的 `drain_ash_kg_s` | −2,276185·10⁻⁴ | −2,278737·10⁻⁴ |
| 差值 | — | 2,552·10⁻⁷（= ash_wf·m·Σdried_exit） |

回归测试 `tests/test_precalc.py::test_diagnostic_signed_drain_reuses_the_shared_balance_formula`：
负余额、非零 `dried_exit` 的小例子上，`signed_drain` 的余额与排出焦炭同 `_drain_terms`
逐位相同，且它与复制式的差恰为 `ash_wf·m·Σdried_exit`（0,009 kg/s）。

重跑（本文所有数值均来自重跑后的 `alternation.json`）：

- 第 3 次预计算的负余额从 −2,2762·10⁻⁴ 变为 −2,2787·10⁻⁴ kg/s；该值只经 `previous_drain_kg_s`
  进入下一次预计算的最底格 `k_exit`，对后续交替的影响小于报告位数。
- 四次交替的闭合差与收敛残差与修正前报告一致：+1,49·10⁻¹²、+1,18·10⁻¹⁰、−1,27·10⁻⁸、
  +5,17·10⁻⁹ kg/s。
- **第 3 次交替在修正后的轨迹上仍超闭合门**（−1,11·10⁻⁶，门限 1·10⁻⁶），按任务卡判据记为
  未达，见第 3.3 节的逐项余项。本报告不以“量级相同”把它记为通过。
